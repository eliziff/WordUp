# Infrastructure measurements

Measured on Windows with installed Word, 2026-09-12. These are individual observations, not latency guarantees or proof of arbitrary template parity. Word UI checks used an owned private desktop; no visible Word window was opened.

The Office bridge now combines the name and control-type conditions inside the UI Automation provider. Previously it retrieved name matches and fetched each type across process boundaries. It still requires exactly one match and checks process ownership. Responses separate `lookup_ms` and `action_ms` to expose the remaining cost.

| Operation | Earlier observation | Provider-filter observation |
| --- | ---: | ---: |
| Font Size ComboBox inspection | 1,900 ms | 162 ms |
| Expand | 4,460 ms | 2,142 ms |
| Collapse | 4,633 ms | 2,200 ms |

The final two responses reported Expanded and Collapsed respectively. Their lookup times were 68 and 136 ms; action calls themselves took 2,061 and 2,036 ms. The action delay remains unresolved. Timing alone does not identify whether Word, UI Automation, or an adapter causes it.

In the same run, Microsoft Open XML SDK validation took 625 ms first call and 8.7 ms reused; oletools binary inspection took 148 ms first call and 7.2 ms reused. First-call numbers vary with OS file caches. The SDK accepted the tested feature-lab DOTM; oletools extracted three VBA modules and form strings. This does not establish VBA compilation or behavior parity.

SDK, binary-inspection and UI helpers together occupied approximately 113 MiB of working set while active. This excludes Word and the Go host. Helpers are lazy, use BelowNormal priority, and exit after 30 seconds idle or session shutdown. An independent lifecycle check observed the SDK helper disappear after 32 seconds and then successfully validate using a fresh helper with `helper_reused=false`. Session shutdown also completed. Measurements came from `workspaces/feature-lab/reports/infrastructure-provider-filter.jsonl` and `helper-idle.json`; these local development artifacts are not distributed.

Conditional-compilation regression tests now reject nonnumeric and non-finite conditions instead of silently choosing the false branch. The port still has limited numeric/type semantics and does not replace native VBA compilation. Parser and Office package tests passed after this change.

## XML assertions inside native suites

Use `xml.snapshot` before and after an operation, then a suite step such as:

```json
{"name":"Preserve document XML","operation":{"op":"xml.compare","target":"$output/before.xml","file":"$output/after.xml"},"assert":[{"path":"/equal","kind":"equals","expected":true}]}
```

This compares namespace-aware XML and returns raw hashes and the first difference. Optional `operation.named.xml_policy` uses the same explicit `attributes`/`elements` exclusions as the agent `xml.compare` tool. No document metadata is ignored by default. Invalid policy keys fail the step. Ordinary suite reporting retains the result and assertion outcome; agents need no separate comparison script.
